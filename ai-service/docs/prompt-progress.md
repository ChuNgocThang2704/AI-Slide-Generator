# Progress against the original AI-slide refactor prompt

Scope: `ai-service` slide generation only; video generation is excluded. This is a code-level assessment, not a claim that real generated presentations are better yet.

| Original requirement | Current status | Evidence / gap |
| --- | --- | --- |
| A. Audit call graph, config, risks | Mostly complete | `ai-slide-audit.md` records the call graph and inventories; some live costs remain unmeasured. |
| B. Incremental boundaries, config, provider preservation | Partial to substantial | Per-request isolation, shared workflow seam, typed config groups and explicit context exist. Provider behavior was preserved, not fully abstracted behind a new gateway. |
| C. Content planning and long documents | Partial | `ContentPlan`, weighted allocation and outline-first long-document path exist with legacy fallback. Planning still uses summarized/truncated inputs in places; section-level bounded concurrency has not been fully unified with the new planner. |
| C. Prompt/document grounding | Partial; sparse-source adjustment unverified live | Uploaded files retain document mode even when short. Planning now discourages invented filler; post-generation source audit allows up to two targeted repairs and rejects unresolved claims. The sparse `numbers_dates` fixture last failed closed; no successful post-adjustment live run yet. Long sources (>30,000 characters) remain outside this guard. |
| C. Structured validation and targeted repair | Substantial but incomplete | `QualityIssue` and field-targeted coherence repair exist. Several older global text/refinement passes remain. |
| C. Semantic duplicate detection | Implemented with tuning pending | Exact plus embedding check exists, with fallback and tests. Threshold is still a function parameter, not a typed quality-policy setting; false-positive rate needs a corpus benchmark. |
| D. Simplified finalization and structure lock | Partial | Shared finalization primitives and explicit policies exist. Legacy repeated enrich/provenance and other global passes remain pending evidence-based removal. |
| E. Design preparation | Initial boundary complete | Post-lock `DesignProfile` and controlled layout intents exist. No adaptive theme generator, renderer wiring, visual validator or re-layout yet, as requested for this phase. |
| F. Evaluation | 9 of 10 fixtures now complete live, none fabricating claims | `late_evidence` and `numbers_dates` were fixed (retry, deterministic literal-quote fallback, and a new `sparse_document_slide_cap` that shrinks the slide count for thin sources) and now complete cleanly. The remaining 7 fixtures were also run live and completed without a fabricated claim in manual spot checks; lecture vs. presentation mode was correct in both mode-sensitive fixtures. `revision` was not run (the benchmark runner does not support it). No versioned human rubric, no latency/cost baseline, and the sweep was not run on one consistent model (a mid-sweep 429 forced a switch from `gemini-3.1-flash-lite` to `gemini-3.5-flash-lite`). See `benchmark-2026-09-16.md`. |

Approximate completion: **65–70% of the requested engineering implementation**, improved from 60–65% by today's grounding fixes and the 9-fixture live sweep, but **still not production-validated** by the plan's own bar (Phase D's redundant-pass removal and Phase 10's module reorganization have not started; no human-rubric or latency/cost baseline exists). This estimate weights the requested architecture and evaluation deliverables, not line counts or test counts. The remaining work is disproportionately important: the `revision` fixture, a controlled same-model benchmark, source-faithfulness evaluation at scale, configuration/tuning, removal of proven-redundant passes, and final architecture/report deliverables.

The public API was not intentionally changed by these phases. Offline tests passing does not establish that generated slides or visual output improved. Do not remove legacy fallbacks or claim end-to-end completion until benchmark examples pass on the deployed provider stack.
